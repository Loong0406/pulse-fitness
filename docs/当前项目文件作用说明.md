# 当前项目逐文件作用说明

依据：2026-10-26 当前 1.2.2 源码，包含排版后的文件。用于理解职责、调用关系和验收定位。

当前 Java 共 74 个文件：app 功能代码 25 个、core 功能代码 30 个、server 功能代码 12 个、测试代码 7 个。Android XML 共 47 个。内部类归在所属 .java 文件下说明；不把一个内部类重复计为一个文件。

## 先理解三个模块

| 模块 | 运行在哪里 | 职责 |
| --- | --- | --- |
| app | 手机/安卓模拟器 | 页面、控件、网络请求、权限与手机本地存储。 |
| core | 手机和 Java 后端都可复用 | 档案/计划模型、生成规则、校验、状态机与接口。 |
| server | 电脑上的 Java 进程 | HTTP 服务、模型 API 对接和 JDBC/MySQL。 |

app → core，server → core；app 与 server 通过 HTTP JSON 通信，没有直接导入对方模块的类。core 不依赖 android.*。

## 验收优先看的调用链

启动：AndroidManifest → PulseApplication → AppContainer；桌面入口 LoginActivity → LocalSessionStore 判断身份 → MainActivity。

AI 计划：PlanScreen → BackendActivity 检查权限 → FitnessViewModel.generate(true) → TrainingFacade → RemotePlanGenerator → HTTP /api/v1/plans → FitnessServer → CompatibleLlmAdapter → 规则校验 → 返回 → 手机 commit 保存 → ObservableState → 页面 bind。

SQL 登录：LoginActivity 勾选服务端 → LoginViewModel → RemotePhoneLoginGateway → AccountHttpHandler → DemoAccountService.verify → JdbcAccountRepository.recordDemoLogin → MySQL。

训练：MainActivity/PlanScreen → WorkoutActivity → WorkoutSession 状态转换与快照 → 完成后历史仓库 → ProgressScreen/WeeklyChartView。

## 当前数据边界

- pulse_auth 保存本机登录身份；pulse_data 保存档案、计划、记录、收藏和快照；pulse_settings 保存服务连接和加密网关令牌等。
- MySQL 当前保存演示用户和登录事件，不保存/同步训练计划；不同演示身份暂共用手机训练资料。
- 演示验证码不发送短信；有 SQL 用户记录也不代表验证了手机号所有权或建立了生产服务器授权会话。
- FitnessViewModel/LoginViewModel 是自定义普通 Java 类，ObservableState 是自定义观察者工具，没有使用 AndroidX ViewModel/LiveData。
- AI 规则检查失败时，后端可以明确回退 LOCAL；手机无法连到后端时会报错，用户可主动选择本地计划。

## 工具生成和运行文件怎样看

build/、.gradle/ 是构建输出与缓存；R、BuildConfig、合并后的 Manifest、APK 等由工具生成，不在这些位置修改业务代码。.idea/ 是 IDE 的个人工程状态，.run/PULSE.run.xml 是项目共享的运行配置。

.runtime/ 内包含开发网关令牌、日志、诊断脚本、排版前备份与验证报告，不属于 App 功能源码，不作为验收代码目录逐项计数，也不应对外分享。deliverables/ 中的 APK 和 SHA-256 是交付产物。

当前 SQL、AI、权限、红黑主题与源码排版以本说明、当前源码及相关专题文档为准。
